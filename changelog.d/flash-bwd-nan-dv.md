kind: Fixed: flash_sdpa backward gives NaN dV for a NaN attention row (it was finite)
---
The bespoke flash attention backward (`baracuda_kernels_flash_sdpa_{f32,f16,bf16,f64}_backward_run`, `FlashSdpaBackwardPlan`) rebuilt each probability as `p = exp(s - lse)` but set `p = 0` whenever `lse` was not finite. That guard is right for `lse = -inf` (a fully masked row: zero gradient, unchanged) and wrong for a NaN `lse`, which the forward produces for a row holding a NaN query or a NaN or `+inf` score: torch's `dV = P^T dO` is then NaN everywhere, and the kernel returned a FINITE `dV` (the NaN row's contribution silently dropped). `dQ` and `dK` were already NaN through the `D = rowsum(dO * y)` term, so only `dV` hid the NaN; a diverging model got finite value gradients. The guard is now `lse == -inf` only. NaN in V or in dO, a finite input, and the fully masked row (zero gradient) are unchanged.

**Affected published versions** (read from the published `baracuda-kernels-sys` .crate files, not tags): 0.0.1-alpha.26 (the first published version that contains the flash backward; alpha.20 to alpha.24 are not on crates.io) through 0.1.0-alpha.209; the guard is present in the .crate of alpha.26, 27, 60, 202 and 209. Reach: Fuel's origin/main binds no flash_sdpa backward symbol (grep 0 hits for `flash_sdpa_backward` / `FlashSdpaBackward`; the same grep finds the forward binding, 1 hit); lightbulb 0 hits. Not shown to be a vulnerability: no GitHub advisory and no RustSec advisory found.

Device test `attention_backward_nan` (f32, f16, bf16; sm89): the finite control matches a CPU f64 oracle; NaN in Q, NaN in K and a `+inf` Q component each give an all-NaN `dV` (red on the old kernel: 2048 of 2048 `dV` elements finite, in all three dtypes); NaN in V and in dO already matched. UNPROBED: the vendored FA2 backward, the naive `SdpaBackwardPlan` (it takes the saved attention matrix, so a NaN passes through), a NaN V at a causally masked-out position (UNSPECIFIED, as in the forward).

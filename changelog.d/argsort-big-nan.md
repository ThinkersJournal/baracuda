kind: Fixed: `ArgsortPlan` on rows over 1024 elements ordered a NaN with the sign bit set below `-inf`
---
`ArgsortPlan` for `row_len > 1024` runs a CUB segmented radix sort, which orders a float by its bit pattern. A NaN with the sign bit set (`0xFFC00000` f32, `0xFFF8000000000000` f64) therefore came out FIRST in an ascending sort and LAST in a descending one, while every other path (and the NaN-largest convention of #429/#430) puts NaN largest. A positive NaN was already correct. The keys are now staged through a small kernel that rewrites every NaN to the positive quiet NaN before the radix pass; only indices are returned, so nothing observable changes except the order. `-0.0` and `+0.0` already tied in index order on this path (measured) and are unchanged. Affected: `baracuda-kernels` and `baracuda-kernels-sys` from 0.0.1-alpha.54 (the first tag containing `baracuda_sort_big.cuh`, added 2026-05-27 by 254ea978b) through 0.1.0-alpha.188. `tests/sort_nan_audit.rs` now generates sign-bit NaNs at every length including `n = 2000` (64 violating rows before, 0 after) and gains `argsort_big_zeros_of_both_signs_are_ties`.

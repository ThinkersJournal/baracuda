kind: **Fix**: `xtask test-gpu` takes the GPU lock per test binary; a second `gpu-run` waits instead of failing
---
- **`xtask test-gpu` holds `Global\gpu-run` for one test binary at a time (PM 2026-11-12).** It used to hold the lock across the whole `cargo test`, so a 7-12 h device-tests job starved every other lane's short GPU run (Fuel waited from ~01:43Z). Phase 1 still compiles unlocked (`cargo test --no-run --message-format=json-render-diagnostics`); phase 2 runs `scripts/gpu-run.ps1 -Project baracuda -- <test exe> --include-ignored ...` once per executable named by the JSON artifact lines, from the package directory with `CARGO_MANIFEST_DIR` set, stopping at the first failing binary unless `--no-fail-fast`. `GPU_RUN_TIMEOUT_MIN` defaults to 180 for these calls (a waiter used to abort after 45 minutes). Doc tests are no longer run by `test-gpu` (`cargo test --doc` errors on a package without a library); none is gated on a device, which is not enforced. Off Windows nothing changes.
- **`scripts/gpu-run-mutex.ps1`: a second opener no longer gets "access denied".** `New-GpuRunMutex` created the mutex with a security descriptor, which asks for `MUTEX_ALL_ACCESS` even when it already exists; the ACL grants only `Synchronize|Modify`, so every second `gpu-run` failed with "cannot open ... (access denied)" instead of waiting. Reproduced on a test mutex under pwsh 7.7 before the fix. It now opens an existing mutex with `Synchronize|Modify` first, creates only when absent and retries on a create race. Fuel's and Vulkane's copies carry the same code.
- **`scripts/gpu-run.ps1`: no more false "RECLAIMED stale GPU lock from DEAD pid" on a contended acquire.** The lockfile was read before the wait, and a holder that finished cleanly is dead by the time the waiter looks; it is now re-read after the mutex is owned.
- **Tests.** `scripts/test-gpu-run-interleave.ps1` (CI, Windows, both PowerShell editions) runs two lanes against a unique test mutex with a private lockfile: per-binary holds order `ABABABAB` (pwsh 7.7) and `BABABABA` (powershell 5.1) and never overlap; a whole-run control orders `AAAABBBB`, so the test can see starvation. xtask unit tests `one_lock_hold_per_binary_in_order`, `stops_at_first_failure_unless_no_fail_fast` and `parses_test_executables_and_unescapes_windows_paths` (7 pass; the parser fixture matches real cargo output). `test-gpu-run-mutex-acl.ps1` still passes under both editions. Not run end to end: a real `cargo gpu-test` on the GPU (the lock is held by CI run 43080166028).

kind: Changed: BREAKING numerics: `argmax` / `argmin` return the first NaN
---
`ArgReducePlan` (`ArgReduceKind::Argmax` / `Argmin`; f32, f64, f16, bf16; i64, u32 and i32 index outputs) replaced its best value only when the new value was strictly greater (`>`) or smaller (`<`) than it. A NaN is neither, so it counted only when it sat at index 0: `argmax [1, NaN, 0, 5]` returned 3 and `argmin` returned 2, while `[NaN, 1, 5]` returned 0 and `[1, 5, NaN]` returned 1. The result now follows torch.argmax / argmin and Fuel's CPU kernels: the FIRST NaN wins and stays, otherwise the first index of the extremum (ties keep the earlier index; `-0.0` and `+0.0` are equal). `[1, NaN, 0, 5]` gives 1 for both, `[1, 5, NaN]` gives 2, `[3, NaN, NaN, 1]` gives 1, `[NaN, NaN, NaN]` gives 0, `[5, 5, 2, 2]` gives 0 and 2. Rows without a NaN are unchanged. f64 is compared in f64 (a pair equal at f32 precision is not a tie; measured, unchanged). Affected: `baracuda-kernels` and `baracuda-kernels-sys` from 0.0.1-alpha.21 (the first tag containing `arg_reduce_fp.cu`, added 2026-05-17 by cd6845ad4) through 0.1.0-alpha.192. New `tests/arg_reduce_nan.rs` (9 device tests: Fuel's 8 spec vectors per dtype, a 400-row by 37 property test per dtype against a closed form, and the f64 precision vector): 8 of 9 failed before (234 wrong rows each), 9 of 9 pass after.

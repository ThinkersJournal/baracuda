Stacked on the plain `mbarrier` statements (S12a-2). `Tcgen05Commit` as the IR spells it, one `bar` on a `Shared` allocation of 64-bit elements with no multicast and no `ctaMask`, lowers to `tcgen05.commit.cta_group::1.mbarrier::arrive::one.shared::cluster.b64 [bar]` (the barrier's shared address, which is part of the `shared::cluster` window), with the `sm_100a` `#error` guard and interface requirement of the other tcgen05 statements. Runtime UNVERIFIED on hardware (RTX 4070, no tensor memory): NVRTC for `sm_100a` compiles an alloc / barrier init / commit / relinquish / dealloc kernel and `ptxas -arch=sm_100a` accepts the PTX; a corrupted mnemonic is rejected by ptxas ("Unknown field '.cta_group::1'", the text test fails too), so the test can fail; no claim beyond what ptxas accepted. The multicast form with a `ctaMask` is HELD (ROADMAP S12 (b); pm-kernels 2026-11-27, findings not advice, not a clearance) and not built: a test asserts the source has no `multicast` and no `ctaMask`. `Tcgen05Mma` and `Tcgen05Ld` are still refused. ROADMAP S12 records S12a-3 as shipped. The CI device run is queued, not claimed.

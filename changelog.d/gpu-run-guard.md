kind: Added: device tests refuse to run outside gpu-run (baracuda_driver::init checks GPU_RUN_HELD under the test-support feature)
---
A structural guard (ROADMAP S19), after a plain `cargo test --features device-tests` ran device tests without the machine-wide GPU lock twice on 2026-11-27. With the `test-support` feature (a dev-dependency feature, so never in a production build), `baracuda_driver::init()` calls `test_support::require_gpu_run_lock()` once the driver library has loaded and BEFORE `cuInit`, and panics unless `GPU_RUN_HELD` is `1` (`scripts/gpu-run.ps1` exports it into its child, so every binary launched by `cargo gpu-test` and the CI device job has it) or `BARACUDA_ALLOW_UNGATED_GPU=1` (a machine with no other user of the GPU). The refusal does not touch the device, and a machine with no CUDA driver library fails in `init()` before it, so hosted CI and a laptop without NVIDIA are unchanged. Measured on the RTX 4070: the same `exclusive_scans` test binary, bare with `GPU_RUN_HELD` unset, fails 2 of 2 device tests in 0.00 s with a message naming `gpu-run`; through `gpu-run` 2 of 2 pass. New test `gpu_run_guard.rs` in `baracuda-driver` (a child process without the marker is refused and names `gpu-run`; with the marker it gets through `init()`, run only from a parent that itself holds the lock) and a unit test of the marker rule. NOT covered: device tests that never call `baracuda_driver::init` (the cudart-based `baracuda-runtime` tests, 9 files); the row records it as open. `docs/DEVICE-TESTS.md` documents the guard. The CI device run is queued, not claimed.

kind: Added: IndexBoundsPlan, a device-side index bounds check (ROADMAP E4 first slice)
---
New `IndexBoundsPlan`: a device-side bounds check that lets a caller raise on an out-of-range index, as torch does (ROADMAP E4, first slice). The indexing plans (`IndexSelectPlan`, `GatherPlan`, `ScatterPlan`, `ScatterAddPlan`, `IndexAddPlan` and their backwards) are unchanged: they still SKIP an out-of-range or negative index and leave the output cell untouched. `IndexBoundsPlan::run` counts the values of a contiguous i32 or i64 index buffer outside `[0, bound)` into a device `u32` word, reading only the index buffer (it adds no kernel parameter and changes no existing ABI, so one check serves every indexing op and dtype); `clear = false` accumulates one word across several buffers. `IndexBoundsPlan::check` synchronises the stream, reads the word and returns the new `Error::IndexOutOfRange { count }` (the error enum is `#[non_exhaustive]`). `run` adds no host sync, so a captured graph replays it; `check` is the sync point. Not done in this slice: fusing the check into the indexing launches (a second pass over the index buffer is the cost of not touching the kernels), masked ops, and strided index views (make the index contiguous first). Device test `index_bounds`: exact counts for i32 and i64 (negative, `== bound`, `i32::MAX`/`MIN`, an i64 that wraps to a valid i32), zero for in-range and empty, accumulate versus clear, a 2M-element buffer, and the pairing with `IndexSelectPlan` (the cell is skipped, the check reports it). Red on `origin/main`: the plan does not exist (the test does not compile).

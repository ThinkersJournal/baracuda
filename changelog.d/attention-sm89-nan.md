kind: Fixed: the sm89 flash attention kernels turned a NaN query row into zeros; NaN and +inf now propagate (and a flash_decoding regression test)
---
The two sm89 flash kernels (`baracuda_kernels_flash_sdpa_sm89_{f16,bf16}_run` and the `_strided_run` siblings that `FlashSdpaPlan` uses on sm_89) had the same row softmax as the generic flash kernel fixed in the previous release: a row maximum taken with `if (v > m)`, which a NaN never wins, and a non-finite maximum read as "fully masked, write zeros". A query row holding a NaN came out as an all-zero output row with `lse = -inf` and the NaN disappeared; a `+inf` score did the same. A NaN or `+inf` score now poisons its row (output and `lse` NaN) and only that row; a fully masked row is unchanged (these kernels have only the causal mask, which never masks a whole row), and a NaN value at a masked-out position is unspecified. `flash_decoding` (f16, bf16) was probed and needed no change: a NaN query, an attended NaN key in any split-K chunk, an attended NaN value and a `+inf` query component all already give a NaN head (a NaN chunk sum survives the split-K merge: `0 * NaN` is NaN), so only a regression test was added. The decoding API has no mask, so the fully masked row cannot be expressed there. Affected: `baracuda-kernels` and `baracuda-kernels-sys` from 0.0.1-alpha.26 (the sm89 kernels are in that .crate) through 0.1.0-alpha.198. New `tests/flash_sdpa_sm89_nan.rs` (4 device tests: f16 and bf16, regular and strided): 4 of 4 failed before (a NaN query row returned zeros), 4 of 4 pass after; new `tests/flash_decoding_nan.rs` (2 device tests, f16 and bf16, three split-K chunks): 2 of 2 pass on the unchanged kernel.

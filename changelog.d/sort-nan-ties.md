kind: Fixed: `SortPlan`, `ArgsortPlan` and `MsortPlan` returned unsorted output for rows holding a NaN, and `MsortPlan` was not stable even without one
---
The block-bitonic sort comparator (`cmp_swap_needed` in `baracuda_sort.cuh`) called a NaN "equal to everything" (neither `<` nor `>`), which is not a strict weak order, so a row with a NaN came out unsorted (`[1, NaN, 9, 2]` ascending returned a NaN before the 2). **Separately, and with no NaN involved:** `MsortPlan`'s stable tie-break flipped with the bitonic block direction, so a row of finite values with equal keys could come out with equal keys in descending index order: `msort` was **not stable** although it is documented as stable (a stable sort used for multi-key sorting is silently corrupted by this). Both are fixed with one strict total order over (value, index), **NaN is the largest value** (last ascending, first descending), **equal values in ascending index order**, which also makes `sort` and `argsort` deterministic on ties. The order lives in ONE definition, `baracuda::sort::total_order_precedes`, which `baracuda_topk.cuh` now includes too (the top-k fix of alpha.187 had a second copy; there is one now). **Affected published versions: `baracuda-kernels` and `baracuda-kernels-sys` 0.0.1-alpha.26 (2026-05-18, the first release carrying `baracuda_sort.cuh`, read from its published `.crate`; the comparator text is the same) through 0.1.0-alpha.187.** Device audit (RTX 4070, sm_89, f32/f64, both orders, `row_len` 4 to 1000, 2000 for `argsort`): before, `SortPlan` 292, `ArgsortPlan` 292 and `MsortPlan` 302 violating rows (all NaN rows for sort/argsort; 12 NaN-free unstable rows for msort); after, 0. The CUB radix path for `row_len > 1024` (`ArgsortPlan` only) was already correct for a positive NaN (the n=2000 case passes before and after) but orders a NaN **with the sign bit set** by bit pattern, below `-inf`: that is a separate defect, NOT fixed here (ROADMAP row E0c). `-0.0` and `+0.0` compare equal in every path (sorted either way). Tests: `tests/sort_nan_audit.rs` (device-gated).

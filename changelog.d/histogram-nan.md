kind: Fixed: `HistogramPlan` counted a NaN in bin 0
---
`HistogramPlan` (f32, f64) skipped out-of-range values with `if (v < lo || v > hi) continue;`. Every comparison with NaN is false, so a NaN was not skipped: it fell through to `(int32_t)((v - lo) * scale)`, which converts NaN to 0, and was counted in bin 0 (a row `[NaN, 0.1, 0.5, NaN, 1.0]` over `[0, 1]` in 4 bins returned `[3, 0, 1, 1]`, not `[1, 0, 1, 1]`). The test is now `!(v >= lo && v <= hi)`, so NaN is ignored like the values below `lo` and above `hi` (`+-inf` too), which is torch.histc ("elements lower than min and higher than max and NaN elements are ignored"). Inputs without a NaN are unchanged. Affected: `baracuda-kernels` and `baracuda-kernels-sys` from 0.0.1-alpha.24 (the first tag containing `baracuda_histogram.cuh`, 1f0bf74a4, 2026-05-17) through 0.1.0-alpha.196. New `tests/histogram_nan.rs` (2 device tests, f32 and f64; NaN, `+-inf`, out-of-range values and `hi` itself): 2 of 2 failed before (`[4, 0, 1, 1]`, three NaNs counted), 2 of 2 pass after. `bincount` takes integers and is unaffected.

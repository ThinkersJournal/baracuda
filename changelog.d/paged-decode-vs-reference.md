kind: **Fix**: vendored FlashInfer `fastdiv.cuh` patch broke paged decode for `page_size` > 1; new device test against an SDPA reference
---
- **Fix: paged decode read page 0 for every token once a request spanned more than one page (power-of-two `page_size`, the vLLM default 16 included).** The 2026-05 vendor patch that replaced `cuda::fast_mod_div` in `vendor/flashinfer/include/flashinfer/fastdiv.cuh` used a 33-bit magic constant truncated to 32 bits: every power-of-two divisor got quotient 0 and 4999 of the divisors 1..5000 disagreed with true division. Replaced with the Granlund-Montgomery round-up method; it agrees with true division in 20,585,084 host checks (d to 2^32 - 1). The existing smoke test used `page_size` 1 and one token, so it never saw it. Also affects `BatchPagedPrefillPlan` and the other plans that include `fastdiv.cuh` (not separately re-tested).
- **Test: `crates/baracuda-flashinfer/tests/paged_decode_vs_reference.rs`** compares `BatchPagedDecodePlan` with an f64 contiguous-SDPA reference built from the same pages: f16 and bf16, `head_dim` 64/128/256, MHA and GQA group 4, `page_size` 16, shuffled physical pages, garbage in unreferenced pages, `last_page_len` 1 / mid / 16 / 0. Measured on an NVIDIA GeForce RTX 4070 Laptop GPU (local `cargo gpu-test`, not CI): max abs `o` error f16 2.2e-4, bf16 1.7e-3; max abs `lse` error (base 2) 7.8e-7. Fuel's GAP-380 fixtures (16 heads x d64, kv 256): relative error 4.8e-4 (f16) and 3.9e-3 (bf16); 0.034-0.055 ms per eager launch, 0.006-0.018 ms per launch when 8 are captured in a CUDA graph. **CUDA-graph capture works** (`Stream::capture` + `GraphExec::launch`, replay bit-identical to eager).
- **Build: `baracuda-kernels-sys/build.rs` now watches `vendor/`.** Before, editing a vendored header neither reran the script nor invalidated the object cache, so the `fastdiv.cuh` fix did not rebuild anything (the first rerun reproduced the old errors to the digit).
- **Provenance: `vendor/flashinfer/VENDOR.md`.** Checked against `flashinfer-ai/flashinfer` `eee0d75f` (fetched by SHA): `LICENSE`, `NOTICE` and 20 headers byte-identical; the other 7 differ only by the documented patches; `LICENSE-FP16` is byte-identical to `Maratyszcza/FP16` `LICENSE`. Patch #5 text corrected.

kind: **Fix**: `PagedKvAppendPlan` docs and tests had `last_page_len` one off from upstream FlashInfer
---
- **Fix: the `last_page_len` contract of `PagedKvAppendPlan` / `baracuda_kernels_flashinfer_paged_kv_append_decode_*` is now documented as upstream FlashInfer defines it, and the smoke tests check it.** Upstream (`flashinfer-ai/flashinfer` `eee0d75f`, `flashinfer/page.py` `append_paged_kv_cache`, Note: "`kv_indices`, `kv_indptr`, `kv_last_page_len` has incorporated appended k/v") and the vendored `AppendPagedKVCacheDecodeKernel` (`page.cuh`, byte-identical to upstream) take `last_page_len[b]` **counting the new token**, in `[1, page_size]`: the token goes to slot `last_page_len[b] - 1` of the request's last page (`seq_len = (pages - 1) * page_size + last_page_len`; `0` would underflow). Our `paged_kv_append.rs` header, the `last_page_len` field doc and the launcher comment said the opposite ("increment `last_page_len` by 1 *after* the call"), so a caller following them overwrote its last existing token and never wrote the new one. **The wrong side was ours; the kernel was not touched.**
- **Tests (`crates/baracuda-kernels/tests/paged_kv_append_smoke.rs`).** Red first, on an NVIDIA GeForce RTX 4070 Laptop GPU with the fixed `fastdiv.cuh`: `paged_kv_append_f32_basic` failed with `k mismatch got=0 want=0.0699` (the kernel wrote slot 2, the test expected slot 3), and `paged_kv_append_f16_runs_to_completion` / `_bf16_` failed with launcher status 3 (`Unsupported`) because they used `head_dim` 32 (supported: 64, 128, 256), so they had never run to completion. Replaced by three generated tests (f32, f16, bf16): six requests per page size (16 and 12) covering "3 existing + 1 new" (slot 3), the first slot (`last_page_len` 1), the last slot (`page_size`) and single-page requests, shuffled physical pages, and a comparison of the whole K and V caches against the expected contents (the new key/value at slot `last_page_len - 1`, the sentinel everywhere else). The kHND layout is now stated correctly in the file header (it said NHD).
- No API or behaviour change. Callers that followed the old doc must pass `last_page_len` including the new token.

kind: ci: a push to main is no longer replaced by a later push in the device-test queue
---
The "Device tests (self-hosted)" workflow keeps one run per pushed commit instead of one waiting run for all of them (concurrency group `device-tests-<sha>` for a push, `device-tests-nightly` for the schedule, the run id for a manual dispatch; `cancel-in-progress` stays false). Before, each push cancelled the previous push's run while it was still waiting, so while the scheduled run held the single runner no merge's run ever started: of the last 25 runs of the workflow (read 2026-11-28 ~19:20Z), 19 push runs ended `cancelled` (17 of the 19 push runs of 2026-11-27, 2 of the 3 of 2026-11-28; the third was still pending) and only 2 push runs succeeded. The device job is unchanged and still required as before. Cost: the queue now holds every push since the last run started (19 deep on 2026-11-26 when there was no group at all); the per-run recompile (about 6 h, mostly cold nvcc) is a separate runner change (sccache or a persistent target directory), not this PR.

kind: ci: a push to main is no longer replaced by a later push in the device-test queue
---
The "Device tests (self-hosted)" workflow keeps one run per pushed commit instead of one waiting run for all of them (concurrency group `device-tests-<sha>` for a push, `device-tests-nightly` for the schedule, the run id for a manual dispatch; `cancel-in-progress` stays false). Before, each push cancelled the previous push's run while it was still waiting, so while the scheduled run held the single runner no merge's run ever started: of the 25 runs listed on 2026-11-28 (the last 25 of the workflow), 14 push runs from 2026-11-27 and 2 of 2026-11-28 ended `cancelled`. The device job is unchanged and still required as before. Cost: the queue now holds every push since the last run started (19 deep on 2026-11-26 when there was no group at all); the per-run recompile (about 6 h, mostly cold nvcc) is a separate runner change (sccache or a persistent target directory), not this PR.

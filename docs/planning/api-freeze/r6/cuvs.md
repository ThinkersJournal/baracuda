## Findings

1. **The whole crate is empty by default.** `mod imp` is `#[cfg(feature = "cuvs")]` (`lib.rs:107`) and so is `pub use imp::*` (`:778-779`); `default = []` (`Cargo.toml`). With default features the crate exports nothing, and `Cargo.toml` has no `[package.metadata.docs.rs]` (grep `docs.rs`: 0; control: `baracuda-megatron/Cargo.toml` has 1), so docs.rs would render an empty crate. `tests/smoke.rs` is `#![cfg(feature = "cuvs")]` (`:16`), so a plain `cargo test` runs 0 integration tests. Add `features = ["cuvs"]` to docs.rs metadata. The only consumer of `baracuda-cuvs` is the workspace root manifest (grep of `crates/*/Cargo.toml` for `baracuda-cuvs\b`: only itself and `-sys`; the facade has 0 hits for `cuvs`, control: 5 for `nvml` in `baracuda/src/lib.rs`).
2. **`Resources` is `Sync` by accident; the SAFETY comment says the opposite.** `Resources { raw: cuvsResources_t }` and `cuvsResources_t = usize` (`-sys` `lib.rs:171`, read), so the struct is auto `Send + Sync`: the `unsafe impl Send` (`lib.rs:264`) is redundant, and `set_stream`/`sync` and every `build`/`search` take `&Resources`. The comment (`:261-263`) says "concurrent use is not" fine. Decision: add a `!Sync` marker (`PhantomData<*mut ()>`) or retract the comment; breaking later. Not compiled. `IvfFlat`/`BruteForce` hold raw pointers (`!Sync`) and `unsafe impl Send` (`:429`, `:622`) with the one-line "opaque handle; same contract as `Resources`"; `BruteForce` also holds `&DeviceBuffer<T>`, which makes it `Send` only if `DeviceBuffer` is `Sync` (`DeviceBuffer` has only `unsafe impl Send`, `memory.rs:42`; `Sync` through its fields **not checked**).
3. **Public fns panic on bad lengths.** 4 `assert_eq!` on `dataset.len() == n_rows * dim` and `queries.len() == n_queries * dim` (`:450`, `:525`, `:644`, `:697`; grep `assert_eq!`: 4) in `Result`-returning APIs; `n_rows * dim` (`:453`) and `n_queries * k` (`alloc_outputs`, `:357`) are unchecked multiplications. `k == 0`, `n_queries == 0`, `k > n_rows` unvalidated. Decision: return an error (the alias is `baracuda_core::Error<cuvsError_t>`, so a mapping like `alloc_fail`, `:136`, is needed) or document the panics.
4. **`Resources::set_stream` keeps no reference to the `Stream`** (`:286-290`: `stream.as_raw()` passed, struct holds only `raw`). If `Stream`'s `Drop` destroys the stream (not checked), later `build`/`search`/`sync` use a dangling stream. Also `Resources` is dropped independently of the indexes (no lifetime tie; what cuVS does with an index outliving its resources is **not checked**).
5. **Closed enum and public-field structs.** `Metric` (4 variants, `:228`) and the two params structs (`:372`, `:408`, 8 public fields) have no `#[non_exhaustive]` (grep `#\[non_exhaustive\]`: 0; control: `non_exhaustive` finds 2 lines, both `finish_non_exhaustive` at `:436`, `:629`). `cuvsDistanceType` has 22 variants (`cuvs-sys.md` finding 3), so more metrics are likely; adding a field to a params struct breaks any literal without `..Default::default()`. `Metric::Cosine` maps to `CosineExpanded` (`:246`); `BruteForce::build` hard-codes `metric_arg = 0.0` (`:664`), so no parametrised metric. Decision: `#[non_exhaustive]` on all three or a builder.
6. **Errors are thin.** Alloc failure and null params both become generic `cuvsError_t::ERROR` (`:136`, `:146`). `last_error_text` (`:159`) is a free function returning `Option<String>` and not attached to the `Error`; whether the message is thread-local is **not checked**, so concurrent failures may race. `Error` exposes `baracuda_core::Error<cuvsError_t>` (`:122`).
7. **`add_data_on_build` is a public field that can break the type's invariant** (`:384`): the doc says keep `true` so `IvfFlat` owns its data, nothing enforces it. `kmeans_trainset_fraction` ("0..=1", `:380`), `n_lists`, `n_probes` are unvalidated. What cuVS does with `false` or out-of-range values is **not checked**. Decision: drop the field or reject `false`.
8. **Sealed scalar.** `CuvsScalar: DeviceRepr + sealed::Sealed` (`:173`), `sealed` private (`:178`), impls `f32` and (feature `half-crate`) `half::f16`; `dl_dtype` is `#[doc(hidden)]` but pub and returns a `-sys` `DLDataType` (public vocabulary, see `cuvs-sys.md`). No device-id check: outputs use `queries.context()` (`:541`); dataset, queries and `Resources` agreeing on one device is unchecked.
9. **Leak on an error path.** In `IvfFlat::search`, the search params `sp` are created at `:535` and destroyed at `:580`, but `alloc_outputs(...)?` at `:541` returns early between them, so a failed output allocation leaks `sp`. Read, not run.
10. **Dependencies.** `Cargo.toml` lists `baracuda-types`, `-core`, `-cuda-sys`, `-cuvs-sys`, `-driver`, `thiserror`, optional `half`. **`thiserror` is unused**: grep `thiserror` over `src/lib.rs` and `tests/smoke.rs`: 0; control: `baracuda_core` is found 2 times and `baracuda_driver` 4 by the same grep (`baracuda_types` 1, `baracuda_cuda_sys` 1, `baracuda_cuvs_sys` 1, `half` 6). Remove after a build check.
11. **Counts and tests.** `unsafe` appears on 25 lines: 22 `unsafe {` blocks + 3 `unsafe impl` (grep `unsafe`: 25; `unsafe {`: 22; `unsafe impl`: 3). `SAFETY`: 4 (`:261`, `:428`, `:463`, `:621`), 3 on the impls and 1 on a params deref, so 21 of 22 blocks carry no comment. `#[test]`: 1 in `lib.rs` (`non_null_rejects_null_params`, `:768`, only with `cuvs`) + 3 in `tests/smoke.rs`, of which 2 (`brute_force_finds_self`, `ivf_flat_build_and_search`) need `device-tests` and RAPIDS; 1 (`resources_new_does_not_panic`) always runs under `cuvs`. Untested: `f16`, `set_stream`, `sync`, `last_error_text`, every error path and panic, metrics other than `L2Expanded`.
12. **README drift.** Version pin `0.0.1-alpha.63` (`README.md:20`) vs `0.1.0-alpha.176`; the hardware-test command `cargo gpu-test -p baracuda-cuvs --features cuvs` (`:81`) omits `device-tests`, which `Cargo.toml` says gates the on-device tests (how `xtask test-gpu` adds it: **not checked**). The README example is not compiled (`include_str`: 0 in `src/lib.rs`).

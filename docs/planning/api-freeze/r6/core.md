## Findings

1. **`#[non_exhaustive]` on the three error enums does not protect their variants' fields.** `LoaderError` (`error.rs:20`), `Error<S>` (`error.rs:122`) and `BaracudaError` (`error.rs:169`), plus `OsFamily` (`platform.rs:8`), are `#[non_exhaustive]`; the census column is 1 for exactly these 4 enum rows and 0 for the other 43 (agrees with `grep -n non_exhaustive src/*.rs`: attribute lines 20, 122, 169 in `error.rs`, 8 in `platform.rs`; the other hits are doc text and `finish_non_exhaustive()` at `loader.rs:29`). The 13 variants of the three error enums are not marked, and every one is a struct or tuple variant constructible outside the crate: `tests/error_plumbing.rs:55` and `:66` build `LoaderError::SymbolNotFound { library, symbol }` and `VersionTooOld { .. }` from an integration test, which is an external crate (read). So adding a field to `Status`, `LibraryNotFound` (say, the list of searched paths, see finding 5), `VersionTooOld` or `FeatureNotSupported` later is a breaking change for any caller that constructs or destructures them without `..`. `baracuda-nvml/src/lib.rs:643-647` already destructures `VersionTooOld` field by field and rebuilds it (grep hit, not read around it), and 1 file outside core names `VersionTooOld` (control: `git grep -F -e 'Library::open('` finds 23 files outside core). Decision: `#[non_exhaustive]` on the variants that may grow (`LibraryNotFound`, `VersionTooOld`, `Status`, `FeatureNotSupported`, `EnvOverrideUnusable`), which costs one `..` in matches and nothing at construction sites that use the two `library_not_found*` constructors; add a constructor for any variant callers must build.
2. **`Library::open` / `open_at` / `open_with_env_override` are safe functions that run foreign initialisation code, and `open_at` mutates the process `PATH` on Windows.** All three call `unsafe { libloading::Library::new(..) }` (`loader.rs:50`, `:64`, `:99`) and expose the result as safe; the crate's own `symbol`/`raw_symbol` are `unsafe fn` with `# Safety` sections (`loader.rs:174`, `:205`), so the line is drawn at calling, not at loading, a deliberate and defensible choice that is not written down anywhere. Loading a library runs its constructors / `DllMain`, which can do anything, and `open_with_env_override` loads whatever path an environment variable names (`loader.rs:140`). The Windows branch (`loader.rs:107-120`) reads `PATH`, builds `parent;old`, and `set_var`s it: (a) it is a read-modify-write, so two concurrent `open_at` calls can each read the old value and one prepend is lost, which the SAFETY comment's "never a torn one" does not cover (`loader.rs:113-116`); (b) there is no de-duplication, so each successful `open_at` of the same directory grows `PATH` by one entry (5 `-sys` crates call `open_at` in a search loop, `git grep -F 'open_at('`: 5 files, each `Library::open_at("<name>", &full)`); (c) the premise "single-threaded at this point in practice" is not enforced by anything. Decision: document in the public doc of each `open*` that loading executes library initialisers and that `open_at` changes `PATH`; decide whether the `PATH` change should be a separate, explicit, opt-in call (breaking later). Whether Windows resolves bare candidate names against the current directory (Phase 1, `loader.rs:49-51`) is **not checked**.
3. **Three third-party types are in the public signatures.** `LoaderError::Libloading(#[from] libloading::Error)` (`error.rs:60`, makes `From<libloading::Error>` public), `Library::symbol` returns `libloading::Symbol<'_, T>` (`loader.rs:182`), and `Library` wraps `libloading::Library` privately (fine). `Cargo.toml` takes `libloading` through the workspace (`Cargo.toml:181` of the root: `libloading = "0.9"`), so a `libloading` 0.10 is a breaking change of this crate, not just of the dependency list. `LoaderError::Libloading` is produced by exactly one path in this crate (`open_at`'s `?` at `loader.rs:99`; `symbol` throws the libloading error away, `loader.rs:193`, so the variant's doc "platform-specific diagnostics" is true for one entry point of seven) and 0 files outside core name `LoaderError::Libloading` (control: 1 file names `VersionTooOld`). Decision: keep and accept the coupling, or wrap the cause in a `Box<dyn Error + Send + Sync>`; `raw_symbol` already returns a plain `*mut ()` and is the shape to prefer.
4. **`&'static str` everywhere forces a leak or a static for dynamic names, and `versioned_library_candidates` returns what `open` cannot take.** `Library::open(name: &'static str, candidates: &[&'static str])` (`loader.rs:38`), `LoaderError::{LibraryNotFound, SymbolNotFound, VersionTooOld}` fields are `&'static str` (`error.rs:25-53`), but `platform::versioned_library_candidates(..) -> Vec<String>` (`platform.rs:180`) is the helper 9 `-sys` crates call (`git grep -F`: cublas, cudf, cufft, curand, cusolver, cusparse, npp, nvjpeg, tensorrt). A `Vec<String>` cannot be passed as `&[&'static str]` without leaking each string. How the 9 crates bridge it is **not checked** (read the first lines of `baracuda-cublas-sys/src/loader.rs`, which returns the `Vec<String>`, not the call site of `open`). Loosening `&'static str` to `&str`/`Cow` in arguments is non-breaking; loosening the enum fields is breaking (finding 1). `symbol` also takes `&'static str` and copies it into a `Vec<u8>` to add a NUL (`loader.rs:184`) and then calls `CStr::from_bytes_with_nul(..)` followed by `to_bytes_with_nul()` (`:185-191`), which is a round trip over the same bytes; an interior NUL is reported as `SymbolNotFound`, a synthetic error. Decision: settle the string lifetimes before the freeze.
5. **README and docs promise error detail the type does not carry; 16 placeholder docs.** README says `LoaderError` "includes the searched paths and OS-level error detail" (`README.md:17-19`). `LibraryNotFound` carries `search_paths: usize`, a count (`error.rs:31`), and both loops in `Library::open` discard the libloading error with `if let Ok(..)` (`loader.rs:50`, `:64`), so the OS-level reason for each failed attempt is gone: the "missing dependency on a chained .so" case the `Libloading` doc cites (`error.rs:56-58`) comes back as `LibraryNotFound` with no cause. `BaracudaError::Context` is documented "attach a path or other context (e.g. a missing PTX file)" (`error.rs:197-198`) but holds `&'static str` (`:202`), so a path cannot be attached. The `EnvOverrideUnusable` and `Libloading` variants print their cause in the `Display` string **and** expose it as `source` (`error.rs:59`, `:76`; thiserror treats a field named `source` and `#[from]` as the source), so an error reporter that walks `source()` prints the cause twice (read, not run). 16 fields carry the doc `Value field.` (`grep -c 'Value field' src/error.rs`: 16; control: the same grep with `Free-form context` finds 1), which says nothing; `VersionTooOld`'s doc and Display name `cuGetProcAddress` and "baracuda's driver loader" (`error.rs:43-47`) in a crate whose doc says it "does not know about any particular NVIDIA library" (`loader.rs:4`). Also `library_not_found` and `library_not_found_with_search` (`error.rs:92`, `:101`) differ only in `search_paths: 0`; one constructor would do.
6. **`Library` soundness, unsafe accounting, and the SAFETY comments.** `loader.rs` has 6 `unsafe {` blocks in non-test code (`:50`, `:64`, `:99`, `:117`, `:183`, `:212`), 2 `pub unsafe fn` (`symbol` `:179`, `raw_symbol` `:211`) with 2 `# Safety` sections (`:174`, `:205`), and 3 `unsafe {` blocks in tests (`:260`, `:274`, `:286`, all `env::{set,remove}_var`); `platform.rs` has 2 more in tests (`:248`, `:254`). Total over `src` and `tests`: 11 `unsafe {` blocks (6 + 3 + 2) and 2 `unsafe fn`; `grep -n unsafe` returns 15 lines (11 + 2 + 2 doc-comment mentions at `loader.rs:166` and `:176`). `SAFETY:` comments: 3 (`loader.rs:113`, `platform.rs:246`, `platform.rs:253`; control: `grep -n unsafe` finds the 15 above). So 1 of 6 non-test blocks has one; the 5 `libloading` calls and `symbol`'s two blocks rely on the `# Safety` docs. The doc for `symbol` asks that `T` be "a function-pointer type" but nothing checks it, while `baracuda-cuda-sys/src/driver.rs:619` region has a `debug_assert_eq!` on `size_of::<T>()` in its own resolver; the core one has none. `raw_symbol` returns `*mut ()` and copies the pointer out of the `Symbol` (`loader.rs:213-214`); the safe `Library` drops (and unloads, per `libloading`, **not checked**) while the pointer lives, which the `# Safety` section says. The test comment "tests in this module run single-threaded" (`platform.rs:246`) is false for the harness: cargo runs tests of one binary on parallel threads, and the `loader.rs` tests call `Library::open`, which calls `library_search_paths`, which reads `CUDA_PATH` (`platform.rs:60-66`) while `search_paths_include_env` mutates it. `std::env` serialises its own readers, so the practical risk is a wrong path list in a concurrent test, not UB; the comment should say what actually makes it acceptable.
7. **Error-type shape.** (a) `Error<S>` carries the bound `S: CudaStatus + Send + Sync + 'static` on the type itself (`error.rs:125`) and on the `impl`s (`:150`, `:208`); `CudaStatus: Copy + Debug + Eq` (`baracuda-types/src/status.rs:14`, grep). A bound on the definition is a freeze commitment (it cannot be dropped without a semver-compatible but still visible change, and it is repeated by every user that names `Error<S>`). (b) `From<Error<S>> for BaracudaError` is lossy and one-way: `Status` becomes four copied fields and the typed `S` is gone (`error.rs:212-217`); `BaracudaError` has 0 uses outside this crate (`git grep -F BaracudaError -- crates`, files outside core: 0; control: `baracuda_core` found in 55 files), so the "process boundary" type the README advertises has no consumer in the workspace. (c) `Error` and `BaracudaError` duplicate `Loader` and `FeatureNotSupported` word for word (`error.rs:135-136` / `:185-186`, `:139-144` / `:189-194`). (d) No error enum is `Clone` or `PartialEq`; `baracuda-nvml/src/lib.rs` has a `clone_error` that rebuilds `LoaderError` by hand (see `r6/nvml.md` finding 2), a symptom of `libloading::Error` being neither. (e) `Error::check` is an associated function on the generic enum (`Error::check(FakeStatus(0))`, `tests/error_plumbing.rs:31`); a free `check(status)` or a `CudaStatus::check` method would not need the `S` inference. None of these is a defect; they are shape decisions that are hard to change afterwards.
8. **`platform` docs drift, and hard-coded lists.** (a) `versioned_library_candidates`' doc example (`platform.rs:172-176`) calls it with three arguments (`"cublas", "12", "11.0"`) where the signature takes `(name: &str, preferred_majors: &[&str])`, and claims Windows yields `cublas64_12.dll, cublas64_11.dll, cublas64_110.dll`; the code (`:189-197`) turns `"11.0"` into `cublas64_11.dll` and then appends `cublas64.dll`, never `cublas64_110.dll`. The Linux line (`libcublas.so.12, libcublas.so.11.0, libcublas.so`) matches the code. (b) `library_search_paths` doc says Windows searches `%ProgramFiles%\NVIDIA GPU Computing Toolkit\CUDA\v*\bin` (`:53`); the code pushes the `...\CUDA` directory itself (`:84-90`, with the comment "We can't glob at const time"), a directory that holds version subdirectories and no DLLs, so that entry can never resolve a library. The Linux doc omits `/opt/cuda`, `/usr/lib/aarch64-linux-gnu` and `/lib/wsl/lib`, which the code adds (`:74-81`). (c) The Windows `CUDA_PATH_V*` list is a fixed 7 names ending at `V13_0` (`:92-100`); a CUDA 13.1 install is found only through `CUDA_PATH`. (d) `is_wsl2` matches `microsoft` or `wsl` in `/proc/version` (`:37-42`), a pattern WSL1 also matches (from memory, **not checked**); the name promises WSL2. It has 0 users outside core (`git grep -F is_wsl2`: 0 files; control `versioned_library_candidates`: 9 files) and neither has `library_search_paths` (0 files), so both are public API with no caller in the workspace. (e) `driver_library_candidates` and `runtime_library_candidates` are `const fn`; `const` is a freeze commitment, and README's "per-library default search-path lists" (`README.md:25-26`) is one global list plus two candidate lists, for the driver and the runtime only. (f) `OsFamily` is correctly `#[non_exhaustive]` (`platform.rs:8`); its `Unsupported` variant already covers the not-Linux-not-Windows case, so the attribute guards a future `MacOs` and costs matches a `_` arm.
9. **`stream_mode`: doc contradicts the code; three paths to `StreamMode`; README names a function that does not exist.** `init` returns `Result<(), StreamMode>` and its doc says `Err` carries "the mode that was already installed" (`stream_mode.rs:21-22`, section starting at the line before `pub fn init` at `:25`); the body is `STREAM_MODE.set(mode)` (`:26`), and `OnceLock::set` returns `Err(value)` with the **rejected argument**, not the installed one (std semantics, from memory, **not checked** against docs; the test at `:55-56` asserts only `is_err()` and `get() == prior`, so it would pass either way). A caller that logs "already set to {mode}" would log the wrong thing; either fix the doc or return `get()`. README refers to `stream_mode::init` / `stream_mode::current` (`README.md:11`); there is no `current`, the function is `get` (`stream_mode.rs:31`; control: `grep -n 'pub fn' src/stream_mode.rs` finds `init` and `get`). `get()` latches the default on first read (`:32`), so any library call that happens before `init` makes a later `init` return `Err` forever; that is documented, and 1 file outside core (`baracuda-cuda-sys/src/driver.rs:619`) calls `stream_mode::get()`. `StreamMode` is reachable as `baracuda_core::StreamMode` (`lib.rs:20`), `baracuda_core::stream_mode::StreamMode` (`stream_mode.rs:17`) and `baracuda_types::StreamMode`: three paths, one type. It is **not** `#[non_exhaustive]` in `baracuda-types` (`baracuda-types/src/stream_mode.rs:22-23`: derive line, then `pub enum StreamMode`; grep context only) and `driver.rs:619` matches both variants with no wildcard, so freezing core freezes a closed 2-variant enum that lives in another crate; `Feature` is `non_exhaustive` (`version.rs:83`, grep) and `CudaVersion` is an opaque `u32` newtype. No `init`-succeeds test exists (comment at `stream_mode.rs:39-43` explains why).

## Recommended order

1. Findings 1 and 4 (variant-level `#[non_exhaustive]`, string lifetimes): both change what callers write or construct.
2. Findings 5 and 3 (what the error carries: search paths and the OS cause, `libloading` types in signatures): decide before the freeze because they change the enums' fields.
3. Finding 2 (document and decide the `PATH` mutation and load-executes-code contract) and finding 9 (fix the `init` doc or return value, README `current` -> `get`, decide the three `StreamMode` paths and its closed shape).
4. Findings 6, 7, 8, 10, 11, 12 as cleanup: SAFETY comments on the 5 unannotated non-test blocks, fix the three `platform` docs, drop or justify the 2 caller-less public fns, rewrite README against the code, add tests for `open_at`, `symbol`, `raw_symbol` and `BaracudaError::from`.

Nothing in this review was built, run, or checked against `libloading`'s or std's documentation: findings 1, 4 (signatures), 5, 6 (counts), 8 (a, b, c), 10, 11, 12 are read from source and greps with the controls stated; findings 2 (Windows search order), 3 (`libloading` contents), 6 (unload behaviour), 8 (d) and 9 (`OnceLock::set` return) rest in part on behaviour of other code recorded here as **not checked**.

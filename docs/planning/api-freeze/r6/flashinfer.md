## Findings

1. **Freezing this crate freezes `baracuda-kernels`' types, and each type has three public paths.** Every name is `pub use baracuda_kernels::..` (`attention.rs:23`, `sampling.rs:43`, `lib.rs:98-104`); the kernels crate itself re-exports the same 37 plan names at its root (`baracuda-kernels/src/lib.rs:694-709`, read). So `baracuda_kernels::X`, `baracuda_flashinfer::attention::X` and `baracuda_flashinfer::prelude::X` are one type: a field added to a descriptor here is a change to the kernels API, and the version of `baracuda-kernels` is a semver dependency of every row. `#[non_exhaustive]` lives in the kernels crate, not here: 4 of the 37 plan-family names carry it (`Fp8KvDtype`, `PerRowSampler`, `SamplerKind`, `BatchPagedPrefillDescriptor`; grep of `attention/` and `random/` with a manual look at the item under each hit, `batch_paged_decode_fp8.rs:32`, `batch_paged_prefill.rs:65`, `perrow_spec_sampling.rs:28`, `topk_topp_sampling.rs:61`); I did not count the rest, so whether the other descriptors and `Args` structs are open for field additions is **not checked** (the crate doc's own example builds `BatchPagedDecodeDescriptor` and `PagedKvCacheDescriptor` as struct literals, `lib.rs:74-85`). Decision: the freeze of this crate is the freeze of those 37 types; review them in the `baracuda-kernels` pass, not here.
2. **Feature gating is by behaviour, not by type, and is documented in two places that disagree with the kernels crate.** Crate doc `lib.rs:55-61`: with `flashinfer` off, plans exist, `select`/`can_implement` validate, `run` returns `Error::Unsupported`. `batch_paged_decode.rs` has 2 `cfg(feature = "flashinfer")` and 2 `Error::Unsupported` (`:145`, `:166`; counted by grep, the gating at each site not read). README line 84 says the plans "are also re-exported [in `baracuda-kernels`] under `flashinfer` cargo feature"; `baracuda-kernels/src/lib.rs:688-709` has no `cfg` on those `pub use` lines (read), so the re-export is unconditional. A default build therefore compiles a crate whose 11 plan types fail at run time (`TokenPenaltyPlan` excepted, `lib.rs:60-61`); `default = []` (`Cargo.toml:15`) is a decision (compile-time absence versus run-time `Unsupported`), and is hard to reverse once users rely on either.
3. **Docs and README drift.** (a) README `:59-60` names a `query_workspace_size` step; `grep -n 'pub fn query_workspace_size'` over `baracuda-kernels/src/attention` and `random` returns 0, while `pub fn workspace_size` is found (`batch_paged_decode.rs:269`), and the crate doc example uses `workspace_size()` (`lib.rs:87`). (b) `sampling.rs:26-32` narrates a bug history ("Phase 66 fixed the launcher", "vendored FlashInfer sampling kernel (v0.6.12)") and README `:70-73` lists build phases: internal project history in the stable docs, and the v0.6.12 claim is **not checked**. (c) The "f16 / bf16 / f32, head_dim in {64, 128, 256}" claim (`lib.rs:25`, README `:21`) is taken from the doc and **not checked** against the plans. (d) README is not `include_str!`ed (grep 0 in `src`; control: `SPDX` matches 3 files), so nothing compiles its example; the `lib.rs` doctest is `no_run` with its body behind `cfg(feature = "flashinfer")` (`lib.rs:66`), so it compiles nothing in a default build.
4. **`prelude` and the root differ by one name.** The root exports `PrecisionGuarantee` (`lib.rs:102`); the prelude's last block (`lib.rs:127-130`) lists 9 support names and omits it (read; the prelude's two `pub use` blocks list 23 and 14 plan names, matching the root). Either the omission is intended (then say so) or it is an oversight; adding it later is non-breaking, removing from the prelude is not. The prelude also re-exports `Error` and `Result`, which shadows `std::result::Result` for a glob importer: a standing complaint about preludes, and a decision.
5. **`pub use baracuda_flashinfer_sys as sys` publishes a second crate's whole API.** `lib.rs:108` re-exports the `-sys` crate as `baracuda_flashinfer::sys`; its manifest calls it "a thin re-export facade" over `baracuda-kernels-sys` (`baracuda-flashinfer-sys/Cargo.toml:4`, read; the `-sys` source was **not read**). Everything public there becomes this crate's surface and any `-sys` break is a break here. Decision: keep (and freeze both together), or drop the re-export and let callers depend on `-sys` directly.
6. **Dependencies and tests.** `[dependencies]` (`Cargo.toml:31-32`): `baracuda-kernels` 7 hits in `src/*.rs` (`grep -c baracuda_kernels`: 2 + 3 + 2), `baracuda-flashinfer-sys` 2 (`lib.rs`, one a doc link); both used. `[dev-dependencies]` (`:35-37`): `baracuda-driver` 10 hits in `tests/*.rs`, `half` 7 (these two are the positive controls); **`baracuda-kernels-sys` has 0** (`grep -ho baracuda_kernels_sys` over `src` and `tests`: 0). It is unused by name; it may be there for feature unification or linking, which is **not checked** (the `flashinfer` feature already forwards to it through `baracuda-kernels/flashinfer`, `Cargo.toml:25-28`). `unsafe`: 0 in `src` and `tests` (`grep -c unsafe`: 0 for all 13 files); `SAFETY`: 0 (nothing to annotate). Tests: 29 `#[test]` (`grep -cE '^\s*#\[test\]'`: cascade 4, fastdiv 5, fp8 2, paged_decode 2, vs_reference 4, prefill 4, perrow_spec 3, ragged 2, sampling 2, token_penalty 1; `src` 0). 9 of the 10 files are gated by `#![cfg(feature = "flashinfer")]` plus `#![cfg(feature = "device-tests")]`, `token_penalty_smoke.rs:6` by `device-tests` only (grep of `cfg(feature`), so a plain `cargo test` runs 0 of the 29. No test names `prelude` or `sys` (grep 0; control: `baracuda_flashinfer::attention::` found 8 times), so the prelude's contents, the `sys` re-export and finding 4's omission are untested.

## Recommended order

1. Finding 1 (the 37 types belong to the kernels review) and finding 5 (keep or drop `sys`): both decide what this crate's freeze means.
2. Finding 2 (compile-time versus run-time gating) as a freeze decision, with the README line corrected.
3. Findings 3, 4, 6 as cleanup: README against the code, drop phase narrative from docs, settle `PrecisionGuarantee` in the prelude, remove or justify `baracuda-kernels-sys`, add a compile-only test of the prelude paths.

## Findings

1. **Most of the frozen vocabulary is not in this crate, and its freeze is Unpopped's.** `lib.rs:56-69` re-exports 83 names from `unpopped_vocab` (`KernelSku`, `BackendKind`, `OpCategory`, `ElementKind`, `ArchSku`, `LayoutSku`, `EpilogueKind`, `OperandDesc`, the 27 `*Kind` op enums, `Element`/`KernelDtype` and the dtype newtypes, `DispatchTable`, ..., one census row). A crate that is `1.0` here but re-exports a `0.x` crate's types cannot be more stable than that crate: every `unpopped-vocab` minor bump is a public-API change of this crate, whatever its own version says. The pin is `"~0.47.0"` (`Cargo.toml:74`) while the local registry holds 0.22.0 and 0.32.1 (observation of one machine's cache, not a release history). Consequences for the R6 questions you asked: (a) the SKU / descriptor / dtype / backend **`#[non_exhaustive]` judgement cannot be made here**; `lib.rs:23-24` defers to `unpopped_vocab` and the README's lists (`README.md:71-125`) describe enums this crate no longer defines; (b) **the Ozaki encoding is not in this crate**: grep `Ozaki|ozaki` over `crates/baracuda-kernels-types` = 0 hits (control: `unpopped_vocab` in the same tree = 9 hits). From the older 0.32.1 copy, **not 0.47**: `BackendKind::Ozaki { slices: u8 }` packs the slice count in the low 5 bits (`0` = auto, `3..=18` fixed) and a variant flag in the high 3 bits (0 Base, 1 EF, 2 RN, 3 H) (`sku.rs:~165-196`, outside this worktree); the encoding is documented in the variant's doc comment and has a `pub mod ozaki_slices` of `const fn` constructors with a runnable doctest (`sku.rs:~202-224`); "values with any other bit pattern are rejected at plan-select time" (rejection happens in a plan, not in the type, so `Ozaki { slices: 0xFF }` is constructible and is a valid `Eq`/`Hash` key). The same file has 0 `#[test]` (grep -c; control: the doctests above are the only checks I saw); whether 0.47 keeps that, tests it, or wraps it in a newtype is **not checked**. Decision: the freeze review of `unpopped-vocab` (the Unpopped repo) must happen first, and must include the Ozaki byte (a validated newtype or a round-trip test of all 4 flags x `{0, 3..=18}`, plus a rejection test for the unused patterns). This crate's part is only to re-export the same set; `lib.rs:50-55` already makes additions one line and a removal a visible diff, which is the right shape. **Severity: high (blocks a 1.0 claim for the crate), action: sequence after Unpopped; no edit here.**

5. **`elements_per_slot` is a closed list of two types that sizes every view check.** `tensor.rs:304-313` returns 2 for `S4`/`U4`, 8 for `Bin`, and 1 for **every other type**, by `TypeId`. `TensorRef::new`/`TensorMut::new` (`tensor.rs:82`, `200`), `matrix_floor` (`matrix.rs:31`) and `VectorRef::new` (`matrix.rs:216`) divide by it to decide whether a *safe* view fits its slice. A new packed dtype (a 2-bit or 4-bit float, an `S2`) added to `unpopped-vocab` and made a `DeviceRepr + Copy + 'static` carrier (`lib.rs:30-33`: any such type rides these views) would silently get 1. Reasoning (read, not run): if the new type counts `shape`/`stride` in logical elements, answer 1 over-counts the slots needed, so the check errs toward rejecting valid views (safe, but wrong); a *safe-direction* failure only. The unsound direction would need the function to return a number larger than the true packing, which the closed list cannot do for a listed type. So this is a correctness and maintenance hazard, not a present soundness hole. Whether any such dtype exists or is planned is **not checked**; the hazard is that nothing makes a new packed type fail to compile here. The function is public (`tensor.rs:303-304`) and in the census, so the signature is frozen too. Decision: make packing a property of the dtype (an associated const on `KernelDtype`, owned by Unpopped, finding 1) and keep this function as a thin wrapper, or at least add a test pinning the 3 known answers (finding 13). **Severity: low-medium (wrong-answer hazard for a future packed dtype; fails on the safe side).**
6. **Matrix views check a floor, not the footprint; the docs of the two view families promise different things.** `matrix_floor` (`matrix.rs:26-37`) checks only `rows, cols, ld >= 0` and `ceil(rows*cols / elements_per_slot) <= len`; `ld` is never compared to the minor extent and is used only for its sign, so `MatrixMut::new(.., rows: 4, cols: 4, ld: 0)` succeeds. The doc says so plainly (`matrix.rs:20-25`, `45-48`: "the plan that consumes the matrix checks the exact footprint"). `TensorRef`'s doc (`tensor.rs:51-53`) says the opposite for tensors: "every constructor checks ... so a safe plan launch can rely on it". `MatrixRef::new_unchecked`'s `# Safety` (`matrix.rs:72-75`) is layout-dependent ("the footprint the consuming plan will read"), which a caller cannot evaluate without the plan. Result: a safe `MatrixMut` does **not** carry a bounds guarantee, so a plan that trusts it is unsound where the tensor equivalent is not; whether any plan trusts it without its own check is **not checked** (it needs a read of `baracuda-kernels`). Decision before the freeze: either state on `MatrixRef`/`MatrixMut`/`VectorRef` that no launch may rely on the constructor beyond the floor (and have the plan docs say it checks), or add a layout parameter and check the exact footprint. Adding checks later is behaviour-breaking for callers that rely on `ld` slack. **Severity: medium-high.**
7. **`TensorMut` accepts broadcast and overlapping strides.** `required_len` treats a `stride == 0` axis as costing nothing (`tensor.rs:356`) and the constructor has no non-overlap test, so `TensorMut::new(buf, [4, 4], [0, 0])` and `[4, 4], [1, 1]` are accepted (read; the logic has `lo`/`hi` extents only, `tensor.rs:360-384`). For a read view that is the documented broadcast contract (`tensor.rs:25-28`); for a **mutable** view it means many logical elements map to one cell: a write race on the device, not Rust UB, but a deterministic-looking safe API with nondeterministic output. `TensorMut`'s doc (`tensor.rs:59-62`) points back to "the stride / broadcast contract" without saying it does not hold for writes. Decision: reject `stride == 0` on an axis of extent > 1 in `TensorMut::new` (breaking for any caller doing it today, so it belongs before the freeze; `new_unchecked` stays the escape hatch), or document it as a caller duty on every output plan. **Severity: medium.**
8. **`OperandDescExt` is an unsealed extension trait with a panic.** `operand_desc_ext.rs:21` is a plain `pub trait`: any crate can `impl OperandDescExt for MyType`, and adding a second method later is then a breaking change (grep `sealed|Sealed` in the file: 0 hits; control: `lib.rs:28` documents `Element`/`KernelDtype` as sealed in `unpopped-vocab`, found). It exists only because of the orphan rule (`operand_desc_ext.rs:3-9`), which is a reason to seal it, or to make it a free function `operand_desc_from_tensor_ref`. `from_tensor_ref` `assert!`s `N <= MAX_RANK` (`operand_desc_ext.rs:41`) and documents `# Panics`; a rank is a compile-time constant here, so a `const { assert!(..) }` in the body would turn it into a compile error with no signature change. The bound `T: KernelDtype + DeviceRepr + Copy + 'static` (`operand_desc_ext.rs:29`, `37`) repeats what `lib.rs:30` states `KernelDtype` already is (`DeviceRepr + Copy + 'static` plus `KIND`), read from the docs, **not checked against the vocab source**. Also: `align_bytes: u32` is trusted (not validated as a power of two). **Severity: low-medium.**
9. **`Error`: stale branding and public foreign types.** All 7 `#[error(..)]` messages begin with `baracuda-cutlass:` (`error.rs:32`, `36`, `41`, `46`, `55-57`, `67`, `71`; grep -c `baracuda-cutlass:` = 7 matching the 7 variants, control: `Driver` is found once by the variant-name grep), in a crate that is now `baracuda-kernels-types` serving the whole facade (`error.rs:2-4`, `10-13` say so); every `Display` string is also frozen text that log scrapers read. `Error::Driver(#[from] baracuda_driver::Error)` (`error.rs:72-73`, read) makes `baracuda_driver::Error` part of this crate's public API: its freeze becomes this crate's. `KernelInternal(i32)` carries an unnamed status code (`error.rs:67-69`) with no say which library's. `Unsupported(&'static str)` / `InvalidProblem(&'static str)` carry free text, not a code, so callers cannot match on the reason. There is **no `From<ViewError>`** (grep `ViewError` in `error.rs`: 0 hits; control: `Driver` found), so every `MatrixRef::new(..)?` in a function returning `Result<_, Error>` needs a manual `map_err`, while `Error` already has two variants (`BufferTooSmall`, `InvalidProblem`) that mean the same thing. `#[non_exhaustive]` on `Error` is right (doc at `error.rs:19-23`; 7 variants, `error.rs` says "grown every couple of phases"). Decision: rename the prefix (a one-time text change that is not a type change), add `From<ViewError>` (additive; do it before the freeze so the variant mapping is chosen once), and decide whether `Driver` should be boxed/opaque. **Severity: medium.**
10. **`ViewError` is well-shaped; one doc drift.** `Debug, Clone, Copy, PartialEq, Eq`, `#[non_exhaustive]` (`tensor.rs:316-318`), `Display` and `core::error::Error` implemented by hand (`tensor.rs:330`, `343`; `core::error::Error` needs a recent MSRV, **not checked** against `rust-version`). `TooSmall { needed, got }` docs say `needed` is "Elements the view can reach" (`tensor.rs:323`) but `TensorRef::new` stores the value **after** `div_ceil(elements_per_slot)` (`tensor.rs:82-86`), i.e. **slots**, which differ from elements for `S4`/`U4`/`Bin`; `Display` says "elements" too (`tensor.rs:337`). Fix the wording ("slots of `T`"). Both fields are public enum-variant fields on a `non_exhaustive` enum, so adding a field later is breaking only if the variant is not itself `non_exhaustive`: consider `#[non_exhaustive]` on the `TooSmall` variant. **Severity: low.**
11. **`Workspace` is deliberately closed; the reasoning is dated.** `plan.rs:21-26` ("Intentionally NOT `#[non_exhaustive]` ... stable through 27 alphas") is read against crate `0.1.0-alpha.175` (`Cargo.toml:3`): the count is stale. The closed two-variant shape (`None`, `Borrowed(DeviceSliceMut<'a, u8>)`) is hot-path-matched, a sound argument, and the doc commits to a major bump for a third variant. My judgement: it is the one enum in this crate that plausibly **will** grow (pool-backed and stream-cached workspaces are named in the doc itself) and it is matched by every plan's `run`, so the cost of a break is highest here; either accept that with the doc's own promise, or keep it closed and add a `Workspace::len()`/`as_slice()` accessor so plans stop matching on variants. `Workspace` has no accessor at all in the census (2 variant rows, 0 methods), so its public API is its two variants. **Severity: low (decision made, decision wording stale).**
12. **View shapes that are hard to change after 1.0.** (a) Extents are `i32` and counts `i32`, strides `i64` (`tensor.rs:55-56`, `matrix.rs:51-53`, `199-201`), and `VectorRef::len()` returns `i32` (`matrix.rs:245`), not `usize`: a 2^31-element axis is unrepresentable, and `len()` returning a signed 32-bit is surprising next to the slice API (the `is_empty` pair at `matrix.rs:251` exists for the lint). (b) `TensorRef` is `Copy, Clone` (`tensor.rs:49`) but `MatrixRef` and `VectorRef` are `Debug` only (`matrix.rs:49`, `197`) although their only non-`Copy` risk is none (`DeviceSlice` derives `Copy, Clone`, `baracuda-driver/src/memory.rs:1040`); adding `Copy` later is non-breaking, so this is cosmetic. (c) `data()` returns `DeviceSlice` by value on the `Ref` types and `&DeviceSliceMut` on the `Mut` types, the usual split; fine. (d) rank is a const generic (`TensorRef<'a, T, N>`) in every plan signature, a deliberate choice (`tensor.rs:9-12`) that cannot be undone. (e) `required_len(shape: &[i32], stride: &[i64])` is a public free function whose length equality is a `debug_assert_eq!` only (`tensor.rs:359`); with unequal slices in release `zip` silently truncates and returns a smaller answer, so an external caller can under-count. Make it `[i32; N]`/`[i64; N]` or return `None` on mismatch (the latter is additive). (f) `numel`/`is_contiguous` are duplicated verbatim between `TensorRef` and `TensorMut` (`tensor.rs:154-186` vs `269-296`): maintenance, not API. (g) `is_contiguous` returns `false` for a size-1 axis whose stride is not the "expected" one (`tensor.rs:180`), which is stricter than many libraries; documented as "matches the standard layout", so a decision, not a bug. **Severity: low; (a) and (e) are freeze decisions.**

## Findings

1. **The documentation promises a shutdown that does not exist.** The crate doc says nvml "shuts down when the process exits" via "a process-global guard"; `Nvml`'s doc says "clones are cheap and increment a static guard. Actual shutdown happens when the last reference drops". The code: `Nvml { _marker: () }` with `#[derive(Clone)]`, no `Drop` impl, no counter, and `nvml_shutdown` is never called (grep for `shutdown` in `src/lib.rs`: 3 hits, all in doc comments; control: the `-sys` crate defines `nvml_shutdown` at `lib.rs:667`, so the symbol is loadable and unused here). Process exit cleans up, so there is no leak in practice, but a program that wants to release NVML (a long-lived process that finishes monitoring, a test harness) cannot. Decision before the freeze: either implement the documented behaviour (refcount, `Drop`) or rewrite the docs to "initialised once, never shut down" and drop the `Nvml` token's claim to be RAII.
2. **`Nvml` is a token that nothing requires, and init failure is cached forever.** Every `Device` method calls `nvml()` (the loader) directly and never touches `Nvml`; `device_by_uuid(nvml_instance: &Nvml, ..)` and `device_by_pci_bus_id(..)` do `let _ = nvml_instance;`. They take a token to prove init, which is real because `Device` is only built by `Nvml::devices`/these two functions (read: 3 constructors), but both free functions would read better as `Nvml` methods (breaking after the freeze). `INIT: OnceLock<Result<(), Error>>` memoizes a failed first `nvmlInit_v2` too, so a process that starts before the driver is ready never retries; whether that is wanted is a decision. `clone_error` rebuilds the cached error on each call: `Libloading(_)` and any unrecognised variant become a `SymbolNotFound` with an invented `symbol` string ("(libloading error; see first error)"), so a second caller sees a different error from the first. `Error` is `baracuda_core::Error<nvmlReturn_t>`, itself `#[non_exhaustive]` (the `clone_error` comment says so; read, not compiled).
3. **Enums written through an FFI out-pointer and the `-sys` enums are closed.** `power_state`, `performance_state` and `compute_mode` initialise a `PState`/`ComputeMode` local and pass `&mut` to NVML, which writes the enum. If NVML returns a value outside the `-sys` enum (`nvmlPstates_t` has `P0..=P15` and `Unknown = 32`; `nvmlComputeMode_t` has 4 variants; both `#[repr(u32)]`, read), that is an invalid enum value in safe Rust: undefined behaviour. NVIDIA adding a compute mode or a P-state is not hypothetical, from memory and **not checked**. The six re-exported enums (`ClockType` 4, `ComputeMode` 4, `EccCounter` 2, `MemoryError` 2, `MemoryLocation` 8, `PState` 17 variants, counted from the `-sys` source) have 0 `#[non_exhaustive]` (grep on the crate and on `-sys`). Decision: read into a `u32`/raw integer and convert (`TryFrom`, with an `Unknown`/`Other(u32)` arm), then `#[non_exhaustive]` on the public enums; this changes the `-sys` types, so it belongs with the `-sys` freeze.
4. **`Device` is `Copy` and `unsafe impl Send + Sync` on a bare pointer.** `#[derive(Copy, Clone)] pub struct Device { handle: nvmlDevice_t }`, with `unsafe impl Send/Sync` carrying no comment at all (the file has 0 `SAFETY` comments, grep, finding 9). NVML documents device handles as thread-safe for most calls, from memory, **not checked**; nothing in the crate says so. `Device` is not tied to the `Nvml` token by lifetime or ownership, so it outlives any shutdown (moot while shutdown never happens, finding 1). `Device::as_raw` is a safe fn returning the raw handle: the usual "use with care" doc; harmless to read. Decision: add the argument as a comment, and decide whether `Copy` is the intended freeze (it matches `Nvml: Clone`).
5. **Raw integers where the API has a vocabulary.** `temperature_threshold(threshold: u32)`, `pcie_throughput(counter: u32)` and `register_events(event_types: u64)` take NVML's `NVML_*` constants as bare integers, and `nvlink_active(link: u32)` / `nvlink_version(link: u32)` take a link index with no `Device` method to learn the count (`NVML_NVLINK_MAX_LINKS` is not exposed in the crate; grep 0). `temperature()` hard-codes `NVML_TEMPERATURE_GPU`. `cuda_driver_version` returns an `i32` documented as "a packed integer" (the encoding, 1000*major + 10*minor, is from memory, **not checked**, and not stated). `field_values(&mut [nvmlFieldValue_t])` passes `values.len() as c_int` (silent truncation above `i32::MAX`, not reachable in practice) and exposes the union as `value: [u64; 2]` with a `value_type` the caller must interpret. Each raw integer is a freeze commitment to NVML's numbering; typed wrappers added later are non-breaking, so this is a "decide, do not rush" row.
6. **Public vocabulary is `-sys` structs.** `memory_info` returns `nvmlMemory_t`, `pci_info` `nvmlPciInfo_t`, `compute_processes`/`graphics_processes` `Vec<nvmlProcessInfo_t>`, `EventSet::wait` `nvmlEventData_t`, `field_values` takes `nvmlFieldValue_t`; all public `repr(C)` structs with public fields (read in `-sys`). Their layouts and field names become this crate's API, and a version-suffixed NVML struct (`nvmlMemory_v2_t` exists in `-sys`, "falls back to v1" in its doc; `memory_info` uses v1 `nvmlMemory_t`, and `nvmlMemory_v2_t`'s `reserved` field is therefore not reachable from this crate, read) cannot be swapped in without a breaking change. Recommendation: either freeze `-sys` and this crate together, or return small owned structs (as `Utilization` already does) for memory, PCI and processes. `compute_processes`/`graphics_processes` also drop the first call's status (`let _ =`), then call again with the learned count; a process appearing between the calls returns the NVML error (`INSUFFICIENT_SIZE`, from memory, not checked) rather than retrying, which is safe but flaky.
7. **Privileged setters are plain safe methods.** `set_applications_clocks`, `set_power_limit_mw`, `set_ecc_mode`, `set_compute_mode` change GPU state for every process on the machine. They are memory-safe and NVML requires root/administrator (from memory, **not checked**), so `unsafe` is not warranted; the docs say nothing about privilege or machine-wide effect, and `set_ecc_mode` documents "after the next driver reload". Recommendation: document the privilege and scope on each; keep them safe.
8. **`EventSet`.** Owns an `nvmlEventSet_t`, frees it in `Drop` (errors ignored, like the other crates), no `Clone`. It holds a raw pointer, so it is `!Send` and `!Sync` by the auto-trait rules (not compiled; no `assert_not_send` test) while `Device` is `Send + Sync`: a monitoring thread cannot own an `EventSet` that a worker thread registers devices on, or wait on one from another thread. Whether NVML allows that is **not checked**. `EventSet::new` is a `Result` constructor with no `Default`, correct. `wait(timeout_ms: u32)` uses `u32::MAX` as "forever", a sentinel; a `Duration`/`Option<Duration>` would be clearer and is breaking later. `as_raw` is safe and shared-borrow, so a caller can free the set behind the wrapper's back only through unsafe FFI of their own.
9. **Result-returning getters, tests, unsafe accounting.** No getter returns `Result` without a failing path (each does a loader lookup and an NVML status check; no `Ok(..)` with an infallible body), so there is no finding-6-style removal. `gpu_utilization_percent` returns `Option<u8>` and swallows the error (`.ok()`), documented as "an honest no-signal"; `u.gpu.min(100) as u8` keeps it in range. 1 `#[test]` (`query_device_health`, gated by `device-tests`) in `tests/gpu_smoke.rs`; it covers `init`, `driver_version`, `devices`, `name`, `memory_info`, `temperature`, `power_usage_watts`, `utilization`, `gpu_utilization_percent` (9 of 62 items by name). No test touches `EventSet`, the setters, ECC, PCIe, NVLink, `field_values`, the two lookup functions, `clone_error`, or `cstr_to_string` (the one unit-testable helper; it does `from_raw_parts(buf.as_ptr() as *const u8, buf.len())`, sound for an `i8` buffer, read). `src/lib.rs` has 52 lines containing `unsafe` (2 are `unsafe impl`, 1 is the slice in `cstr_to_string`, the rest FFI calls) and 0 `SAFETY` comments (control: the same grep finds the 52); the FFI calls pass stack buffers with their own `len()`, which reads correctly, but no comment states it, and the fixed buffers (80 driver version, 96 name, 96 UUID, 64 serial) are matched against NVML's buffer-size constants only from memory, **not checked**.
10. **Dependencies, gating, README drift.** `Cargo.toml` lists `baracuda-types`, `baracuda-core`, `baracuda-nvml-sys`, `thiserror`. **`baracuda-types` is not used** (grep for `baracuda_types` in `src/lib.rs` and `tests/gpu_smoke.rs`: 0; control: `baracuda_core` is found 4 times by the same grep). `thiserror` is not named in `src/lib.rs` either (no `thiserror` or `derive(Error)` in the file, grep 0, control: `baracuda_core` found), so it is a second unused direct dependency unless it feeds the macro of a type not in this crate: remove after a build check. No feature gating on the API: everything is always compiled, and the `-sys` crate loads `libnvml`/`nvml.dll` lazily, so docs.rs renders all 62 rows (the manifest has no `[package.metadata.docs.rs]`, not needed here). The umbrella exposes it as `baracuda::nvml` behind the `nvml` feature (`baracuda/src/lib.rs:149`, read). README drift: (a) its example calls `nvml.device_count()` and `nvml.device(i)`, neither exists (grep for `device_count` and `fn device(`: 0; control: `fn devices(` is found), so the example would not compile and is not compiled because the README is not `include_str!`ed (0 hits); (b) it claims "encoder/decoder" utilization, "power-management mode", "persistence mode" and "NVLink capability, throughput" coverage (grep for `persistence`, `encoder`, `decoder`: 0 in `src/lib.rs`); the crate has `Utilization { gpu, memory }`, power-limit get/set/range, and `nvlink_active`/`nvlink_version` only; (c) "Comprehensive" overstates 62 items (46 methods) against NVML's surface.
11. **Small items.** `Nvml::devices` returns a `Vec<Device>` built eagerly with `Vec::with_capacity(count)`; fine. `device_by_uuid`/`device_by_pci_bus_id` map an interior NUL to `Error::Status { INVALID_ARGUMENT }`, a synthetic NVML status, acceptable. `Device` has a manual `Debug` and `Nvml` a manual `Debug`, so `missing_debug_implementations` is satisfied; `Utilization` derives `Default, Eq`. `#![warn(missing_debug_implementations)]` is the only crate-level attribute: there is no `#![deny(missing_docs)]`, and every public item read has a doc comment (read, not grep-counted).

## Recommended order

1. Finding 3 (enum out-parameter UB) with the `-sys` freeze, since it changes the public enums; and finding 6 (own structs for memory, PCI, processes) in the same pass.
2. Finding 1 (shutdown: implement or retract the docs) and finding 2 (`Nvml` methods for the lookups, init-failure caching), together since both change `Nvml`.
3. Findings 4, 5, 8 (`Device`/`EventSet` thread-safety argument, typed selectors, `Duration` timeout) as freeze decisions.
4. Findings 7, 9, 10, 11 as cleanup: privilege docs, `SAFETY` comments, README rewritten against the code, unused dependencies removed, more tests.

Nothing in this review was built, run, or checked against NVIDIA's documentation: findings 1, 2, 6, 9 (counts), 10, 11 are read from source and greps with the controls stated; findings 3, 4, 5, 7, 8 rest in part on NVML behaviour recorded here as **not checked**.

## Findings

1. **README and the plan signatures disagree.** README example calls `ColumnParallelLinearPlan::<f32>::new(&ctx, handle)` and `plan.forward(stream, batch, &x, &w_local, &mut y)`; the source has `new(tpctx, batch: i32)` (`lib.rs:766`) and `forward(stream, x, w_local, bias_local, y_local, y_full)` (`:839`), and a `Handle` is created inside `new` (`:783`). The README block is not compiled (`include_str`: 0 in `src/lib.rs`), and the crate doc has no example. Rewrite the example from the tests.
2. **`bias` is a dead parameter, and `ColumnParallel` output is not `[batch, out]`.** Both `forward`s take `Option<&DeviceBuffer<T>>` (`:844`, `:1138`), length-check it, then always return `InvalidArgument` if `Some` (`:869`, `:1158`). Freezing it freezes a placeholder: drop it until Tier 2 or implement it. For `batch > 1`, `y_full` is `[world_size, batch, out/N]`, not `[batch, out_features]` (`:828-833`, documented, "matches Megatron-LM"), and the plan needs both `y_local` and `y_full` from the caller; the README table says "`all_gather` -> `Y` `[B, out]`", which is true only for `batch == 1`.
3. **Three `unsafe fn` are public on a public trait.** `row_major_gemm_nt/nn/tn` (`:272`, `:288`, `:305`) are `#[doc(hidden)]` (grep `doc(hidden)`: 3) but `pub`, callable downstream as `<f32 as MegatronGemmScalar>::row_major_gemm_nt`, and so semver-visible; the trait is sealed (`sealed::Sealed`, `:318`) so no downstream impls, but it also has the foreign supertrait `NcclScalar` (`:259`), so any change to `baracuda-nccl`'s impl set moves this crate's. Decision: move the three methods onto a private sealed supertrait. The `f32` impls call the safe `baracuda_cublas::gemm` (`blas_scalar.rs:542`, whose own comment says sizes are the caller's responsibility) inside `unsafe fn` with no block or comment; the half impls call `unsafe gemm_ex` with a SAFETY comment: asymmetric, not wrong. The contract ("`m`,`n`,`k > 0`", sizes) holds on the plans' paths via `new` (`:767-777`) and `check_len`.
4. **Context and plans: validation split, panics, `!Send`.** `TensorParallelContext::new` is infallible and unvalidated (`:166`) and copies `rank`/`world_size` once; `partitioned_out_features`/`partitioned_in_features` panic via `assert!` (`:217`, `:235`, documented `# Panics`); the plans' `new` validate with `Result` (`:767-782`, `:1078-1093`). Each plan owns a cuBLAS `Handle` (`:783`, `:1094`) and borrows `&Communicator`; `Communicator` has `unsafe impl Send` only (`baracuda-nccl/src/lib.rs:214`; grep `unsafe impl` in that file: that one), so `&Communicator` is not `Send` and the context and plans are not `Send` by the auto-trait rules (not compiled). Decision: intended (build the plan inside each rank thread) or not. Shapes are `i32` (`in_features`, `out_features`, `batch`): fine on 64-bit after the `> 0` checks, 32-bit not checked.
5. **Accessor asymmetry.** Column plan has `out_per_rank`, row plan `in_per_rank`; neither exposes `batch`, `in_features` or `out_features` (all private `tpctx_*` fields, `:727-730`, `:1043-1046`), though `Debug` prints them. Small, additive later.
6. **`Error` shape.** `#[non_exhaustive]` (`:92`; grep `#\[non_exhaustive\]`: 2 lines, 1 attribute at `:92`, 1 doc mention at `:88`). `Cublas(#[from])` displays with `{0}` and carries a source; `Nccl` and `Driver` display with `{0:?}` and use hand-written `From` (`:121-131`) with no `#[source]`; inconsistent. Three foreign error types are public in the enum, so their freezes couple to this one. `InvalidArgument(&'static str)` is stringly (messages at `:768-781`, `:870`); `BufferLengthMismatch { what, got, expected }` is structured. `baracuda-kernels` re-exports 5 names including `Error as MegatronError` (`baracuda-kernels/src/lib.rs:677-683`), so the facade freezes with this crate.
7. **Features and docs.rs.** Only `half-crate` (opt-in `f16`/`bf16`). `[package.metadata.docs.rs] no-default-features = true` is a no-op (`default = []`) and leaves the `f16`/`bf16` impls (`:411-681`) out of docs.rs; use `features = ["half-crate"]`. The comment above `half-crate` (`Cargo.toml:25-27`) says it enables `baracuda-kernels` features; the list has none (`:28-32`).
8. **Dependencies.** `Cargo.toml` lists `baracuda-driver`, `-cublas`, `-nccl`, `-types`, optional `half`, `thiserror`. **`baracuda-types` has no use**: grep `baracuda_types` over `src/lib.rs` and `tests/*.rs`: 0; control: `baracuda_driver` 4, `baracuda_cublas` 4, `baracuda_nccl` 4, `thiserror` 1 (`use thiserror::Error`, `:77`), `half::` 10 in `src/lib.rs`. It is referenced only as `baracuda-types/half-crate` (`Cargo.toml:30`), which `baracuda-nccl`'s `half-crate` already enables (`baracuda-nccl/Cargo.toml:24`): remove after a build check.
9. **Counts, tests, coverage.** `unsafe` on 26 lines: 13 `unsafe {` + 13 `unsafe fn` (grep `unsafe`: 26; `unsafe {`: 13; `unsafe fn`: 13), 0 `unsafe impl`; `SAFETY`: 13 (1 in `gemm_ex_half` `:447`, 6 in the half impls, 6 in the plans `:881`, `:953`, `:971`, `:1171`, `:1236`, `:1254`). The 3 `f32` `unsafe fn` contain no `unsafe` block. `#[test]`: 2 in `lib.rs` (`f32_is_megatron_scalar`, a compile-time bound check; `half_dtypes_are_megatron_scalars`, `half-crate` only) + 6 in `tests/` (`column_parallel_smoke.rs` 2, `row_parallel_smoke.rs` 2, `multi_rank_scaffold.rs` 2), all behind `device-tests`. Four are numerical `world_size == 1` forward/backward checks vs a CPU reference; the two multi-rank tests only build plans (their header says "expected to fail", but they skip through `require_optional!`). Not covered by any test: divisibility errors, bias rejection, `check_len`, `partitioned_*` panics (`should_panic` in the crate: 0; control: `baracuda-driver/src/memory.rs` has 2), `world_size > 1`, `batch > 1` gather layout, `f16`/`bf16`.

## Recommended order

1. Findings 2 and 3 (drop or implement `bias`; gather layout; hide the `unsafe fn`) before the freeze: they change signatures.
2. Findings 4, 6 (`Send` intent, error shape and consistent `Display`/`source`).
3. Findings 1, 5, 7, 8, 9 as cleanup: README, accessors, docs.rs feature, drop `baracuda-types`, host-only tests for the error and panic paths.

Not checked: GEMM transpose mappings and any numerical result, NCCL/cuBLAS behaviour, `Send`/`Sync` by compilation, the builds with `half-crate`, and 32-bit behaviour. Nothing in this review was built or run.
